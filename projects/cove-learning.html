Overview

A tutoring business needs more than a public landing page. Families need a clear way to ask for support; tutors need an application and session workflow; administrators need visibility into operations. Each group should see the information relevant to its role.

My contribution

I co-founded Cove Learning with Ryan and developed the website and platform workflows. The work includes TypeScript/Vite pages, relational data modeling, inquiry and application forms, authentication, private résumé storage, and billing integrations.

Architecture & boundaries

The public site is static and hosted on Cloudflare Pages. Supabase supports authentication, PostgreSQL data, private storage, and backend functions. Stripe handles billing integrations. Role-based access and row-level security separate parent, tutor, and administrator responsibilities.

Forms and security

Application forms use CAPTCHA verification, and applicant résumés belong in private storage. Authentication, data authorization, and payment operations are separate concerns. Building the frontend successfully does not by itself validate database policies, backend functions, or billing behavior.

Current scope

The public site introduces the tutoring service and collects inquiries and tutor applications. The codebase also includes portal entry points and Stripe-related backend work. The homepage dashboard uses sample data; it should not be read as evidence of live operating volume. Portal development and the public marketing site have separate release scope.

What I would evaluate next

Verify each role’s end-to-end workflow, test policy boundaries and payment states, and make deployment history reproducible across the frontend, database migrations, and backend functions.
