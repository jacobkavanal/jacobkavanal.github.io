Hospital data integration

Built a Python and SQLite pipeline to retrieve, validate, and join CMS hospital profiles, cost reports, and inpatient data.

Python · REST APIs · SQL · SQLite

Ingestion, normalization & validation · Research · 2026

Overview

Hospital datasets do not share the same grain or reporting period. Profiles describe hospitals, cost reports describe filings, and inpatient aggregates describe hospital–DRG combinations. A naïve join can multiply rows or attach an arbitrary financial report.

My contribution

As a research assistant at UC San Diego / Terizza AI, I worked on healthcare data integration. The local pipeline retrieves complete selected CMS releases, preserves original API responses, normalizes shared hospital identifiers, and validates records before publishing a SQLite snapshot.

Design decisions

The pipeline keeps the sources in separate tables and joins them at query time. Identifiers remain text to preserve leading zeros and legitimate alphanumeric values. Missing markers become SQL NULL while their original representation is retained. A staged refresh protects the last published database if validation fails.

Join rules

When multiple cost reports could match a hospital, the result is marked ambiguous and financial values are withheld. A report must overlap the inpatient year, but overlap alone does not imply calendar-year comparability. Current ratings also should not be interpreted as historical ratings.

Evidence & validation

The October 22, 2026 verification recorded 5,419 hospital profiles, 6,109 cost reports, and 145,879 inpatient aggregate rows. The joined view preserved 145,879 rows. Repeat ingestion detected no record changes. Tests cover pagination, duplicate keys, missing values, ambiguous joins, and preservation of the previous database after failure.

Limits & next steps

This local research pipeline does not establish production scalability or a transactionally consistent snapshot across CMS APIs. Hospital-wide financial values repeat across DRGs and must not be summed across the join. Company ownership mapping needs a separate, dated crosswalk. A natural next step is making these quality flags easier to inspect.
